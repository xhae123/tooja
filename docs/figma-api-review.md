# 완성된 Figma 화면과 현재 API 비교

**현재 디자인을 구현하기 위한 필수 API 변경은 없어요.** 11개 화면의 데이터와 동작을 현재 API로 제공할 수 있어요. 다만 투자 중지·재개 조작과 예전 설명을 정리해야 해요. 2026-10-14 후속 결정으로 등록 시 지급하며 미로그인 조회는 제공하지 않아요.

- 확인한 디자인: [UI / 03 화면별 와이어프레임](https://www.figma.com/design/UVcdXRekfq9tLLzEmbEyCL/?node-id=50-2)
- 확인 범위: 모바일 P01~P05·확인 모달, 관리자 A01~A04, 공개 대시보드 D01의 이미지와 하단 설명
- 기준: 2026-10-14에 조회한 디자인과 로컬 코드 `59c77e3`
- 이번 검토에서는 서버 코드·DB·Figma를 변경하지 않았어요. 실제 프론트엔드의 동작을 테스트한 결과는 아니에요.

## 화면별로 사용할 API

아래 경로 앞에는 `/api/v1`이 붙어요.

| 화면 | 사용할 API | 연결할 내용 |
|---|---|---|
| P01 투자자 로그인 | `GET /investor/csrf`, `POST /investor/session` | 숫자 4자리 코드로 로그인해요. 소속 팀을 따로 입력하지 않아요. |
| P02 투자 홈 | `GET /investor/teams` | 소속·이름·지급액·투자액·잔액과 20개 팀의 상태·내 투자액을 받아요. |
| P03 팀 투자 | `GET /investor/teams/{teamId}` | 팀 소개·현재 잔액·투자 가능 금액을 받아요. 투자 후 잔액 미리보기는 현재 잔액에서 선택 금액을 빼면 돼요. |
| P03-M 최종 확인 | `POST /investor/investments`, `GET /investor/investment-requests/{requestKey}` | 확정 버튼에서 전송하고, 응답이 끊기면 같은 멱등 키로 결과를 확인해요. |
| P04 투자 완료 | `GET /investor/investments/{investmentId}` | 거래 정보와 **현재 잔액**을 받아요. 투자 생성 응답의 `balanceAfterInvestment`는 해당 거래 직후 잔액이에요. |
| P05 내 투자 내역 | `GET /investor/investments` | 최신순 거래·건수·지급액·총 투자액·현재 잔액을 한 응답에서 받아요. |
| A01 관리자 로그인 | `GET /admin/csrf`, `POST /admin/session` | 관리자도 숫자 4자리 코드예요. 투자자 세션과 별도로 로그인해요. |
| A02 운영 현황 | `GET /admin/overview` | 전체·참가자·운영팀 투자자의 지급·투자·소진 현황을 받아요. |
| A03 투자자 목록 | `GET /admin/investors` | `q`, `teamId`, `kind`, `spendingStatus`로 검색·필터링해요. |
| A04 투자자 상세 | `GET /admin/investors/{investorId}` | 이름·소속·잔액·소진 상태와 최신순 거래 내역을 받아요. |
| D01 공개 대시보드 | `GET /public/dashboard` | 총 투자액·투자한 고유 인원·20개 팀의 순위와 유치금을 받아요. |

## 먼저 디자인에 반영할 내용

### 투자 중지·재개 조작과 중지된 화면이 빠져 있어요

현재 관리자 화면은 조회 전용으로 설명돼 있고, 중지·재개 버튼이 없어요. 투자 홈·팀 투자·확인 모달에도 전체 접수가 중지된 상태가 없어요.

- 관리자 조작: `PATCH /admin/investment-status`에 `RUNNING` 또는 `PAUSED`를 보내면 돼요.
- 투자자 화면: 목록·상세 응답의 `investmentStatus.status`로 중지 안내와 버튼 상태를 표시해요.
- 확인 창을 연 뒤 중지될 수도 있어요. 확정 요청의 `409 INVESTMENT_PAUSED`도 처리해야 해요.
- 중지해도 소개·잔액·내역은 계속 볼 수 있어요.

**API는 이미 있어요. 관리자 조작과 투자자 안내를 디자인에 추가하면 돼요.**

### 소진 상태는 시안처럼 두 가지예요

후속 결정으로 투자자는 사전 등록할 때 100만원을 지급받아요. `UNSPENT`(잔액 남음), `COMPLETED`(잔액 0원)만 제공하므로 시안의 ‘전체 / 미소진 / 소진 완료’를 그대로 연결하면 돼요. 미로그인 목록·필터·집계는 추가하지 않아요.

### 투자자 이름은 사전 등록한 값을 조회해요

2026-10-21 결정으로 관리자 이름 수정 기능을 제거했어요. 행사 전에 DB에 정확한 이름을 등록하므로 A04에 수정 버튼·입력 UI를 추가하지 않아요. 기존 응답 필드 `alias`는 사전 등록 이름을 반환하는 용도로 유지해요.

## 새 디자인 표현은 프론트엔드에서 처리할 수 있어요

- **P02 부스 배치도:** 현재 배치는 팀 번호가 정해진 정적 지도예요. 프론트엔드에서 `teamId`에 부스 위치를 연결하고, 서버의 `investmentState`·`myInvestmentAmount`로 색과 금액을 표시하면 돼요. 위치를 운영 중 변경하는 요구가 생기면 그때 별도 데이터 모델을 검토해요.
- **D01 순위 변화·증가 금액:** 이전 응답과 새 응답을 `teamId`로 비교하면 돼요. 증가 금액은 두 조회 사이의 합계라 단일 거래 금액으로 표현하면 안 돼요. 첫 응답에서는 변화 효과를 표시하지 않아요.
- **D01 유치금 막대:** 각 팀 유치금을 현재 1위 유치금으로 나누면 돼요. 모두 0원이면 막대 길이도 0으로 처리해요.
- **갱신 시각·연결 지연:** 기존 응답의 `asOf`와 클라이언트의 응답 성공 시각으로 표시해요. 1초·2초 갱신도 기존 GET API를 반복 호출하면 돼요.
- **CSV:** 시안에서는 미결 사항이에요. 추가하기로 정하면 현재 목록 응답으로 프론트엔드에서 CSV를 만들 수 있어요. 전용 API는 필수가 아니에요.

## 예전 설명과 예시 데이터는 수정해주세요

- **P01:** 그림에서는 팀 선택이 없어졌지만 하단 설명에는 남아 있어요. 현재 로그인 입력은 코드 하나예요.
- **A01:** 코드 입력 예시는 6자리처럼 보이지만 실제 규칙은 4자리예요. ‘운영진 전용 · 조회 기능만 제공’도 관리자 명칭과 중지·재개 조작에 맞춰 정리해주세요.
- **P05:** 예시 `750,000원`은 10만~70만원, 10만원 단위 규칙에 맞지 않아요. 세 거래 합계는 145만원인데 요약은 70만원이고, 15:20 거래가 마지막에 있어 ‘최신순’과도 맞지 않아요. 예시를 수정할 사항이지 투자 규칙을 바꿀 근거는 아니에요.
- **D01:** 동률 처리는 이미 `1, 1, 3` 경쟁 순위로 정했어요. 하단의 ‘확정 필요’ 표시를 정리해주세요. 같은 유치금이면 팀 번호 오름차순으로 표시해요.
