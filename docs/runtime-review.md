# 운영 구성과 한계

브라우저 → OCI LB+WAF → 단일 앱 VM → private Always Free MySQL로 연결해요. 진입점과 DB는 앱 VM에서 분리하지만 앱은 한 대이며 DB도 단일 노드예요. 앱·DB 장애까지 자동으로 다른 노드가 처리하는 구성은 아니에요.

| 설정 | 적용 범위 | 한계 |
|---|---|---|
| WAF 국가 차단 | Tooja hostname, 한국 IP 허용 | 한국 VPN·한국 IP 공격·IP 오분류 |
| WAF 요청 제한 | IP별 60초 30,000건, 초과 시 60초 제한 | 전체 합산 초당 제한·처리 용량 보증 아님 |
| SQLi·XSS 검사 | API 요청 | 모든 공격 차단 보증 아님 |
| 본문 1MiB | 앱 API 쓰기, chunked 포함 | 총 동시 요청 메모리·응답 크기 제한 아님 |
| LB bandwidth | min/max 10Mbps | 여러 서비스가 같은 대역폭을 공유해요 |
| DB 백업 | MySQL 기본 자동 백업 1일 | PITR·HA·수동 OCI 백업 없음 |
| CPU·메모리 경보 | 사용률 60% 이상이 5분 지속 | 측정·알림 전파 지연이 있어요 |
| 외부 점검 | 서울에서 10분마다 HTTPS 점검, 첫 실패 알림 | 최대 점검 간격과 평가 지연, 모든 사용자 경로 대표 아님 |
| 서버 오류 | HTTP 5xx 1건마다 Discord 이벤트 | 수집·전달 지연 및 재시도 중 중복 가능 |

JVM·연결 풀·DB 작업 지표와 비밀값을 제외한 백엔드 오류·접속 로그를 OCI로 보내요. 사용자 코드·쿠키·CSRF·본문·SQL 원문은 수집하지 않아요. 수집기 자체가 멈추면 heartbeat 경보가 알려줘요.

LB는 Always Free 10Mbps, MySQL은 MySQL.Free예요. WAF는 첫 인스턴스와 월 1,000만 요청 무료 범위가 있어요. 공격으로 요청량이 무료 범위를 넘는 경우까지 비용 0을 보장하는 설정은 아니에요.

네 자리 코드는 사용자가 선택한 재사용 식별 키예요. 해외 차단과 높은 요청 제한만으로 국내 코드 추측을 완전히 막지는 못해요.
