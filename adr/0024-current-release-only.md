# 0024. 성공한 배포의 현재 산출물만 보존한다

- 결정일: 2026-10-05
- 상태: 채택
- 결정 근거: 사용자가 배포 교체마다 이전 이미지와 JAR·배포 파일을 모두 삭제하도록 지정했다.

## 배경

커밋마다 Docker 이미지와 릴리스 파일을 남기면 단일 서버 디스크 사용량이 계속 늘어난다. 사용자는 이전 버전을 긴급히 복구할 필요가 낮으므로, 직전 버전을 보관하는 정책도 원하지 않았다.

## 결정

새 앱·nginx 경유 health·OpenAPI·Allure·배포 커밋 검증이 성공한 뒤 이전 tooja 이미지를 삭제하고 이전 릴리스 디렉터리도 삭제한다. 현재 배포만 남긴다. tooja 전용 builder를 사용하고 성공 후 빌드 캐시도 비운다. 다른 서비스 이미지·캐시는 자동 삭제하지 않는다. DB·DB 백업은 앱 산출물과 구분하여 보존한다.

## 선택 이유와 대안

직전 릴리스 보존은 빠른 롤백에 유리하지만 사용자가 명시적으로 제외했다. 전체 Docker prune은 다른 서비스에 영향을 줄 수 있어 사용하지 않는다.

## 결과와 한계

새 배포 검증에 실패하면 아직 남아 있는 이전 버전으로 복구한다. 성공 후 정리까지 끝나면 이전 릴리스의 서버 파일은 없다. 이후 복귀는 해당 커밋을 GitHub Actions로 다시 배포해야 한다. 캐시를 비우므로 다음 빌드에서 기본 이미지 등을 다시 내려받을 수 있다. DB 백업은 별도 보관 정책이 필요하며 이 결정으로 자동 삭제하지 않는다.
