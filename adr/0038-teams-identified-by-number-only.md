# 0038 팀은 번호로만 식별하고 팀 이름을 저장하지 않기

## 배경

팀 테이블은 `id`(1~20), `name`, `description`을 가졌고, 투자자 API는 `name`을 `serviceName`으로 내보냈어요. 팀 목록·상세, 투자 영수증·내역·거래 상세, 관리자 투자자 상세, 공개 대시보드, 투자자 성과 순위의 기여 내역이 모두 이 필드를 포함했어요.

프론트엔드는 팀을 고르는 화면에서는 `TEAM 02`처럼 번호만 쓰고, 투자 완료·내역에서만 `serviceName`을 붙여 보여 줬어요. 2026-10-31 탐색 테스트에서 이 불일치가 드러났고, 행사 운영 측은 팀 이름을 수집하지 않고 `TEAM nn` 번호로만 표기하기로 했어요.

## 결정

팀 이름 개념을 백엔드에서 제거해요.

- 응답 모델 `Team`, `Investment`, `RankingRow`, `ScoreContribution`에서 `serviceName`을 지워요. 팀은 `teamId`로만 식별하고, 화면 표기(`TEAM 02`)는 프론트엔드가 번호로 만들어요. 팀 소개 `description`은 유지해요.
- MySQL은 Flyway `V4__drop_team_name.sql`로 `teams.name`을 삭제해요. 팀 번호·소개와 계정·거래의 `teams(id)` 참조는 그대로예요.
- 로컬·테스트용 SQLite는 새 DDL에서 `name`이 없고, 이전에 만든 파일은 기동 시 `name` 컬럼이 있으면 한 번 삭제해요.
- 최초 CSV 등록 형식은 `id,description` 두 칸으로 바꿔요. 소개에는 쉼표가 들어갈 수 있어요.
- 조물주 콘솔도 팀을 `TEAM nn`으로만 표시해요.

## 대안

- 컬럼은 남기고 응답에서만 빼기: 저장은 하지만 아무도 읽지 않는 값이 생겨, 수동 등록·콘솔·문서가 계속 이름을 요구하는 것처럼 보여요.
- `serviceName`을 `TEAM 02` 문자열로 채워 계약을 유지하기: 프론트엔드가 이미 번호로 같은 표기를 만들고 있어 중복이고, 의미 없는 필드를 계약에 남겨요.

## 영향과 검증

API 응답에서 필드가 사라지는 **호환되지 않는 변경**이에요. 프론트엔드가 `serviceName`을 읽는 완료·내역 화면은 번호 표기로 바꿔야 하고, 이 변경 사항은 프론트엔드 저장소 이슈로 전달해요. 요청 본문과 경로, 상태 코드, 다른 필드는 바뀌지 않아요.

운영 DB의 팀 이름은 V4 적용 시 삭제되고 되살릴 수 없어요. 현재 운영 데이터는 더미이며, 필요하면 MySQL 자동 백업(1일)에서 확인할 수 있어요.

통합 테스트로 팀 목록·상세, 투자 영수증·내역·거래 상세, 관리자 투자자 상세, 대시보드, 투자자 순위 응답 어디에도 `serviceName`이 없음을 확인하고, 두 엔진의 `teams` 컬럼이 `id, description`으로 같음, 이전 SQLite 파일의 `name` 컬럼 삭제, 두 칸 CSV 등록을 SQLite·MySQL에서 확인해요.
