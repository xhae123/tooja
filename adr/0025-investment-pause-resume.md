# 전체 투자 접수를 중지·재개해요

## 배경

처음에는 관리자가 현재 순위를 캡처하는 방식으로 충분해 시작·마감 기능을 두지 않았어요. 이후 관리자가 신규 투자 접수를 직접 중지하고 다시 실행할 수 있어야 한다는 요구가 추가됐어요. 이전 결정을 이 범위에서 변경해요.

## 결정

전체 접수 상태를 `RUNNING`과 `PAUSED`로 나눠 SQLite에 저장해요. 기존 서비스가 계속 동작하도록 최초 상태는 RUNNING이에요. 서버를 재시작해도 저장된 상태는 유지해요. 관리자 PATCH는 목표 상태를 지정하고, 같은 상태를 반복 요청하면 추가 변경이 없어요.

중지하면 신규 투자만 거절해요. 로그인·최초 지급·소개·잔액·거래·순위 조회는 계속 가능해요. 중지 오류는 요청 키를 소비하지 않아 재개 후 같은 요청으로 다시 투자할 수 있어요. 이미 커밋한 요청은 중지 중에도 원래 결과를 돌려줘요.

상태 변경과 투자 확정은 같은 공정한 JVM 쓰기 잠금과 SQLite 트랜잭션으로 직렬화해요. 먼저 확정된 투자는 유지하고 중지 응답 성공 이후 신규 투자는 거절해요. 상태는 잔액·원장·순위 snapshotVersion을 변경하지 않고 독립 revision으로 구분해요.

## 한계와 검증

영구 마감이나 결과 스냅샷 기능은 아니에요. 관리자가 재개하면 순위가 다시 바뀔 수 있어요. 한 JVM이라는 기존 배포 가정을 유지해요. 두 동시 실행 순서, 권한·CSRF, 일시 거절 후 재개, 기존 영수증 복구, 저장 실패 롤백과 재기동 보존을 실제 SQLite 통합 테스트로 검증해요.
