# 0036 조회 전용 조물주 콘솔과 DB 활동 기록

## 배경

운영 중 사용자가 무엇을 했는지 확인할 수단이 없었어요. 접속 로그는 stdout JSON으로 메서드·경로·상태·소요 시간만 남기고, 설계상 IP·계정·본문을 제외했어요. 관리자 중지·재개도 누가 했는지 남지 않았어요. 인프라 지표는 호스트 수집기가 OCI Monitoring으로만 보내서 서비스 활동과 한 화면에서 볼 수 없었어요.

저장소 소유자 한 사람이 전체 활동과 인프라 상태를 감시할 수 있어야 해요. 프론트엔드는 Vercel에 있고 API 호스트는 PR #8로 화면 제공을 중단했으므로, 운영자 화면은 프론트엔드와 분리된 자리가 필요했어요.

## 결정

API 호스트가 직접 그리는 서버 렌더링 콘솔 `/owner/**`를 제공해요. Thymeleaf 템플릿과 폼 전송만 사용하고 JSON API나 브라우저 스크립트는 두지 않아요. 조회 전용이며 쓰기는 로그인·로그아웃 폼 두 개예요.

조물주는 계정이 아니에요. 환경 변수 `OWNER_TOKEN`(32자 이상)을 해시로만 비교하고, 별도 테이블 `owner_sessions`와 쿠키 `owner_session`(HttpOnly, 12시간, 경로 `/owner`)을 써요. 토큰이 설정되지 않으면 `/owner` 전체가 404예요. 로그인 실패는 IP당 1분 5회로 제한하고, 폼 CSRF는 세션 또는 10분 컨텍스트 토큰과 `Origin == APP_ORIGIN`으로 검사해요. 투자자·관리자 쓰기에 쓰는 `APP_ALLOWED_ORIGINS`에는 API 호스트를 추가하지 않아요. 4자리 코드 체계는 1만 가지뿐이고 서버 측 로그인 제한이 없어 전권 세션에 쓰지 않아요.

모든 `/api/**` 요청은 응답이 끝날 때 `activity_log`에 한 줄 남아요: 시각(epoch ms), requestId, 메서드, 매칭된 라우트, 상태, 소요 시간, 행위자 역할·계정, 행위 이름, 오류 코드, 팀·금액·투자 ID, Origin, **클라이언트 IP 원문**, 소켓 주소, **User-Agent 원문**. 이 결정은 "IP·계정을 로그에 남기지 않는다"는 기존 접속 로그 규칙을 운영 DB 기록에 대해 의도적으로 바꾸는 것이에요. stdout 로그와 OCI 전송은 기존 규칙을 그대로 유지하고, 원문 경로·쿠키·본문·코드·SQL은 어디에도 저장하지 않아요. 클라이언트 IP는 LB가 `X-Forwarded-For`에 **덧붙이는** 구조에 맞춰 오른쪽에서 신뢰 홉 수(`TRUSTED_PROXY_HOPS`, 기본 1)만큼 떨어진 값을 쓰고, IP 형식이 아니면 소켓 주소로 대체해요.

기록은 요청 처리를 막지 않아요. 유계 큐(기본 1만 건)에 넣고 단일 스레드가 최대 499건씩 모아 별도 트랜잭션으로 저장해요. 큐가 가득 차면 버리고 개수를 집계해요. SQLite에서는 지연 트랜잭션끼리 커밋이 끼어들면 업무 요청이 `SQLITE_BUSY_SNAPSHOT`으로 실패하므로 기록 쓰기도 기존 쓰기 락을 공유해요. MySQL(운영)은 InnoDB 행 락으로 충분해 락을 쓰지 않아요. 운영 테이블의 시각은 ISO 문자열이 아닌 epoch 밀리초로 저장해요. `Instant.toString()`은 소수초 길이가 가변이어서 문자열 범위 비교가 틀어지고, 버킷 집계도 숫자가 단순해요.

행위 이름은 컨트롤러·서비스가 요청 속성으로 보강해요(`login_success/login_failed/logout/invest_succeeded/invest_rejected/pause/resume/view_*`). 조회 결과는 90일, 지표 샘플 30일, 시스템 이벤트 365일 뒤 매일 정리해요.

## 대안

- 외부 로그 시스템(OCI Logging)만 사용: 이미 보내고 있지만 IP·계정 없이 보내며, 서비스 데이터(계정·투자)와 조인해 보려면 결국 DB에 있어야 해요.
- Vercel 프론트에 관리자 화면 추가: 프론트 저장소는 외부 팀 소유이고, 전권 화면을 공개 프론트 번들에 두고 싶지 않았어요.
- JSON API + 단일 페이지 앱: 쿼리 허용 목록·CSP·22개 공개 API 수 계약을 모두 건드려야 하며, 혼자 쓰는 조회 화면에는 과했어요.
- 요청 처리 중 동기 INSERT: 투자 트랜잭션과 같은 락 아래에서 매 요청에 쓰기를 추가해 지연을 늘려요.

## 영향과 검증

투자자·관리자 API 계약, OpenAPI 22개 작업, CSRF 허용 Origin, 프론트엔드는 바뀌지 않아요. Flyway V3는 테이블 추가만이라 이전 앱으로 돌아가도 무해해요. 기록은 best effort라 큐 포화·DB 장애 시 일부가 빠질 수 있고 개요 화면에 버린 개수를 보여줘요.

단위 테스트로 행위 이름·IP 판별·유계 큐·보존 정리를, SQLite·MySQL 통합 테스트로 토큰 로그인·제한·Origin 거절·활동 기록 내용(IP·UA 포함, 코드·본문 미포함)·페이지 렌더링·역할 분리·스키마 일치를 확인해요. 실제 Tomcat에서 `/owner/login`과 보호 헤더를 확인해요. CI에는 단위·통합 테스트만 포함해요.
