# ADR 0028: MySQL 스키마는 Flyway SQL로 변경해요

## 배경

기존 SQLite는 시작 시 CREATE TABLE IF NOT EXISTS로 테이블을 준비했어요. 이는 이미 존재하는 테이블의 변경을 적용하거나 변경 이력을 검증하지 못해요.

## 결정과 이유

MySQL 프로필에서 Flyway를 사용하고 `db/mysql/V번호__설명.sql`로 순서·checksum을 관리해요. 이미 적용한 파일은 수정하지 않고 다음 파일을 추가해요. JPA/Hibernate 자동 DDL은 쓰지 않아요.

앱 기동 전에 마이그레이션이 끝나도록 초기화 순서를 연결해요. Flyway clean은 비활성화해요. 초기 SQL에는 계정·데모 투자금 지급이 없고 수동 등록 정책을 유지해요.

## 한계

Flyway는 이전 앱과의 스키마 호환성이나 업무 데이터 정합성을 자동 보장하지 않아요. 스키마 변경도 리뷰·백업·통합 테스트가 필요하고 배포 실패가 DB 변경을 자동 취소하지는 않아요.
