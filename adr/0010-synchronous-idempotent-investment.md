# ADR 0010: 투자는 동기 확정하고 요청 키로 중복 차감을 막는다

기록일: 2026-10-05 · 결정 출처: 구현 선택

## 배경

투자 버튼을 누른 뒤 응답이 끊기면 브라우저는 성공 여부를 알 수 없습니다. 초안에는 202와 처리 중 상태가 있었지만 별도 작업 큐는 필요하지 않았습니다.

## 결정

트랜잭션 완료 뒤 201을 반환합니다. 논리적 투자마다 UUID v4 Idempotency-Key를 받고, 같은 투자자·키·본문이면 최초 성공 영수증 또는 확정 거절을 재현합니다.

## 선택 이유

작업 큐·진행 상태를 추가하지 않고 재전송으로 결과를 복구할 수 있습니다. 같은 키의 팀·금액 변경은 409로 거절합니다.

## 비교한 대안

비동기 202/PROCESSING은 선택하지 않았습니다. 재전송마다 새 키를 생성하는 방법은 원 요청 성공 여부를 분리할 수 없어 사용하지 않습니다.

## 영향과 한계

요청 결과 조회의 404는 미도착·미커밋일 수 있어 실패 확정이 아닙니다. 같은 키·본문으로 재전송합니다. 조회 HTTP 200 안의 REJECTED는 저장된 투자 거절 결과이며 조회 API 자체의 오류와 다릅니다.

## 현재 상태와 구현 근거

구현됨. 입력·CSRF 실패는 요청 결과에 기록하지 않고 도메인 거절은 저장합니다.
