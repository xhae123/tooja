# ADR 0003: 인증은 토큰 대신 DB 세션으로 관리한다

기록일: 2026-10-05 · 결정 출처: 협의된 구현 선택

## 배경

투자자와 관리자를 로그인시키고, 48시간 만료·로그아웃·여러 기기 동시 접속을 관리해야 합니다. 서버는 하나이며 SQLite를 이미 사용합니다.

## 결정

브라우저에는 의미 없는 임의 세션 값을 HttpOnly 쿠키로 보내고, 서버는 그 값의 해시와 계정·만료·폐기 상태를 DB에 저장합니다. 세션은 발급 후 48시간 고정입니다.

## 선택 이유

로그아웃과 만료를 DB의 한 상태로 판정하고, 앱 컨테이너를 교체해도 로그인 상태를 보존할 수 있습니다. 별도 Redis를 추가하지 않고 사용자가 제안한 DB 저장소를 활용했습니다.

## 비교한 대안

JWT 자체로 인증하면 매 요청의 세션 조회를 줄일 수 있지만 즉시 폐기·로그아웃을 운영하려면 추가 정책이 필요합니다. JVM 메모리만 쓰면 재배포 때 세션이 사라집니다.

## 영향과 한계

매 보호 요청에 DB 조회가 있습니다. 쿠키 값은 JavaScript로 읽지 않고 브라우저가 보내도록 해야 합니다. 여러 기기의 세션은 허용하지만 재로그인이 현재 브라우저의 동일 역할 세션을 교체합니다.

## 현재 상태와 구현 근거

구현됨. 세션 원문은 DB에 저장하지 않고 해시만 저장합니다.
